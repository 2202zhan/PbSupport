# PrintBox Support Bot

Отдельный Telegram-бот, который принимает заявки поддержки PrintBox ("не печатает",
"файл не загрузился" и т.п.), сам проверяет SNMP-историю принтера и логи ПК аппарата
через `https://nurtest.space/api`, и просит ИИ (OpenAI) разобрать случай: дать юзеру
совет, уточнить деталь, или подготовить рекомендацию на возврат.

**Деньги двигает только человек.** У ИИ нет инструмента возврата и нет настройки,
которая его включает: самое сильное, что он может — собрать досье и черновик ответа,
а сотрудник подтверждает возврат кнопкой в чате поддержки (`notify.py` — единственное
место в коде, которое вызывает API возврата).

## Установка

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"   # или см. зависимости в pyproject.toml, если редактируемая
                            # установка не нужна - можно установить их напрямую
```

## Конфигурация

Скопировать `.env.example` в `.env` и заполнить:

| Переменная | Что это |
|---|---|
| `SUPPORT_BOT_TOKEN` | токен нового Telegram-бота от @BotFather |
| `PRINTBOX_ADMIN_LOGIN` / `PRINTBOX_ADMIN_PASSWORD` | админ-доступ к API (или `PRINTBOX_ADMIN_TOKEN` вместо них) |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | ключ и модель для решающего вызова |
| `SUPPORT_STAFF_CHAT_ID` | chat_id группы, куда уходят эскалации с кнопками подтверждения |
| `ADMIN_TELEGRAM_IDS` | telegram_id через запятую - эти юзеры видят `/admin` в личке с ботом |
| `REFUND_REVIEW_AMOUNT_CAP` | выше этой суммы (₸) карточка сотрудника помечается «стоит взглянуть внимательнее» |
| `NEIGHBOR_WINDOW` | сколько заказов до/после проверять на признак массового сбоя |
| `PRINT_SIGNAL_WINDOW_MINUTES` | окно поиска события печати после оплаты |

## Запуск

```bash
python bot.py
```

В фоне (production-режим без живого терминала):

```bash
nohup python bot.py > /dev/null 2>&1 &
```

Логи пишутся самим приложением в `support_bot.log` (ротация: 5 МБ × 5 файлов, дальше
старые обрезаются) — не нужно и не стоит перенаправлять stdout в отдельный файл
(`> bot.log`), иначе получится второй, нерotируемый лог-файл, растущий бесконечно.

## Тесты

```bash
pytest
```

Тесты покрывают: разбор и восстановление логов ПК (`log_parser`), парсинг чеков
(`receipt_parser`), сбор фактов и защиту от "протекания" сигнала соседнего заказа
(`diagnosis`), проверку возможности возврата перед показом кнопки (`guard_rules`),
маппинг ответа OpenAI на решение со всеми сценариями отказа и retry на временные ошибки
(`ai_decider`, `openai_utils`), защиту от повторного нажатия кнопки возврата (`notify`),
и UI-хелперы триажа (`triage`). Не покрыт (нужны реальные ключи): `api_client` против
живого API.

## Известные допущения, не проверенные на живых данных

Формат авторизации admin-эндпоинтов, семантика `refund` на стороне PrintBox, и
расхождение часовых поясов между логами ПК аппарата (наивное локальное время) и
таймстампами API.
