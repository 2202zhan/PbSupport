# PrintBox Support Bot 2.0 — переход на диалогового агента

Рабочий чеклист. Полное ТЗ с диаграммами — в артефакте (ссылка в истории чата).
Этот файл обновляется по мере закрытия фаз.

## Суть

Сейчас: дерево меню решает, какой из трёх несвязанных «мозгов» ответит
(скриптовый текст / `ai_decider` / `concierge`). Кнопки маршрутизируют бота.

Станет: один агент с инструментами. Юзер пишет текстом, агент сам решает, что
спросить, что проверить и чем закончить. Кнопки — то, что агент **рисует** под
конкретную ситуацию, а не то, что его **ведёт**.

## Неприкосновенное

- ИИ никогда не возвращает деньги. Возврат — только кнопка живого человека.
- `diagnosis.py` — сбор доказательств
- `guard_rules.py` — блокеры возврата
- `notify.py` — консоль сотрудника: топики, живой чат, кнопка возврата
- `api_client.py`, `receipt_parser.py`, `log_parser.py`

## Фазы

- [x] **0. Каркас и наблюдаемость** — флаг `AGENT_MODE=off|admin|all` (`agent/gate.py`,
      неизвестное значение = `off`), таблица `agent_turns`, `agent/router.py` включён
      перед `triage.router`. Пока в нём нет хендлеров — для юзеров ничего не изменилось.
      14 тестов.
- [x] **1. Память диалога** — таблицы `conversations` / `conversation_messages`,
      TTL 6 ч (`AGENT_CONVERSATION_TTL_MINUTES`), блокировка «один ход за раз» на юзера,
      сжатие головы истории с сохранением хвоста и без осиротевших tool-результатов.
      SQL в `storage.py`, политика в `agent/memory.py`. 14 тестов.
- [x] **2. Ядро агента** — `agent/runtime.py`: петля модель → инструменты → модель,
      бюджеты ≤3 вызова модели / ≤6 инструментов / 45 с, любой отказ → эскалация.
      Инструменты `reply` и `escalate` (`agent/tools.py`), промпт в `agent/prompt.py`,
      Telegram-сторона в `agent/router.py`. Заявка создаётся в момент эскалации.
      23 теста.
- [x] **3. Динамический UI** — `reply(text, buttons[], expect)`, рендер в `agent/ui.py`,
      подписи в таблице `conversation_buttons` (в `callback_data` только id), нажатие =
      сообщение в диалог, клавиатура снимается после тапа, «✋ Позвать человека» под каждым
      сообщением. Файлы больше не проваливаются в меню-бота. Плюс `agent/guards.py`:
      совет обслуживать аппарат заворачивается на переписывание. 33 теста.
- [x] **4. Инструменты чтения** — `service_info`, `check_apparat`, `find_my_orders`
      (`agent/reading.py`). Цифры уходят в `ctx.staff_notes` и модели не показываются —
      утечка счётчиков невозможна структурно. Знание об аппаратах вынесено в общий
      `apparats.py` (его же использует меню-бот). Без названного аппарата инструмент
      возвращает список реальных точек, и агент спрашивает кнопками. 14 тестов.
- [x] **5. Диагностика** — `investigate_order` поверх `gather_evidence` +
      `review_refund_case`. Модели уходит вывод человеческим языком и подсказка «как быть»,
      весь технический разбор (SNMP, логи, блокеры, массовый сбой) — в `staff_notes`.
      Прогресс-сообщение через `ctx.on_progress`. 8 тестов.
- [x] **6. Файлы и чеки** — чек читается в момент отправки, где бы в разговоре это ни
      случилось (`agent/files.py`). Разбор чека уходит в диалог фактом, файл — в карточку
      сотруднику, точные сумма и время — в `investigate_order` как ground truth.
      Фото без OCR принимается и честно помечается непрочитанным. Правило 24 часов
      сохранено. Работа с чеками вынесена в общий `receipts.py`. 7 тестов.
- [x] **7. Эскалация и деньги** — `escalate` умеет `refund_recommended`, `confidence`,
      `draft_reply`; при наличии `Evidence` уходит полная карточка через `send_escalation`
      (кнопка возврата — по `guard_rules`, нажимает человек). Заявка получает аппарат,
      транзакцию и `payment_expected` из проверки. Пока открыт живой чат, сообщения юзера
      идут сотруднику, а не агенту. 6 тестов.
- [x] **8. Эвалы** — 32 сценария через целого агента против фейкового PrintBox
      (`tests/evals/`). На каждом ходу проверяются инварианты: ответ юзеру есть,
      внутренних терминов и наших цифр нет, советов обслуживать аппарат нет, обещание
      передать сотруднику совпадает с фактом эскалации, возврат агентом не вызывался.
      Запуск: `pytest -m evals` или `python -m tests.evals.run`. Первый прогон нашёл
      5 дефектов, третий — зелёный, эскалаций 38%.
- [ ] **9. Переключение** — `AGENT_MODE=all`, неделя наблюдения, удаление FSM.
      `triage.py` 2096 → ~200 строк.
- [ ] **10. Умнее** — преднагрузка заказов юзера на входе, проактив по авариям,
      CSAT, аналитика, сводки сотрудникам.

## Принятые решения

1. **Выбор аппарата** — спрашиваем только когда он реально нужен для проверки.
   Для вопроса про график работы аппарат ни при чём.
2. **Модели** — две: быстрая ведёт диалог, сильная принимает решение про возврат.
   Разговор должен быть быстрым, решение про деньги — точным.
3. **Старое меню** — после переключения удаляем совсем. Два входа = два поведения,
   которые со временем разъедутся.
