# PrintBox Support Bot 2.0 — переход на диалогового агента

Рабочий чеклист. Полное ТЗ с диаграммами — в артефакте (ссылка в истории чата).
Этот файл обновляется по мере закрытия фаз.

## Суть

Сейчас: дерево меню решает, какой из трёх несвязанных «мозгов» ответит
(скриптовый текст / `ai_decider` / `concierge`). Кнопки маршрутизируют бота.

Станет: один агент с инструментами. Юзер пишет текстом, агент сам решает, что
спросить, что проверить и чем закончить. Кнопки — то, что агент **рисует** под
конкретную ситуацию, а не то, что его **ведёт**.

## Неприкосновенное

- ИИ никогда не возвращает деньги. Возврат — только кнопка живого человека.
- `diagnosis.py` — сбор доказательств
- `guard_rules.py` — блокеры возврата
- `notify.py` — консоль сотрудника: топики, живой чат, кнопка возврата
- `api_client.py`, `receipt_parser.py`, `log_parser.py`

## Фазы

- [x] **0. Каркас и наблюдаемость** — флаг `AGENT_MODE=off|admin|all` (`agent/gate.py`,
      неизвестное значение = `off`), таблица `agent_turns`, `agent/router.py` включён
      перед `triage.router`. Пока в нём нет хендлеров — для юзеров ничего не изменилось.
      14 тестов.
- [x] **1. Память диалога** — таблицы `conversations` / `conversation_messages`,
      TTL 6 ч (`AGENT_CONVERSATION_TTL_MINUTES`), блокировка «один ход за раз» на юзера,
      сжатие головы истории с сохранением хвоста и без осиротевших tool-результатов.
      SQL в `storage.py`, политика в `agent/memory.py`. 14 тестов.
- [ ] **2. Ядро агента** — петля модель → инструменты → модель. Бюджеты: ≤3 вызова
      модели, ≤6 инструментов, 45 с. Любая ошибка → эскалация, никогда молчание.
      Инструменты пока два: `reply`, `escalate`. Готово: админ ведёт живой диалог.
- [ ] **3. Динамический UI** — `reply(text, buttons[], expect)`, рендер inline-кнопок,
      `callback_data` через id из БД, нажатие = сообщение в диалог, всегда есть
      «✋ Позвать человека». Готово: кнопки разные под ситуацию.
- [ ] **4. Инструменты чтения** — `service_info`, `check_apparat`, `find_my_orders`.
      Готово: график работы, «кончилась бумага», «прошёл ли платёж» — без меню и без заявки.
- [ ] **5. Диагностика** — `investigate_order` поверх `gather_evidence` +
      `review_refund_case`, прогресс-сообщения. Готово: «оплатил, не распечатал» адаптивно.
- [ ] **6. Файлы и чеки** — приём фото/PDF в любой момент, парсинг → факты в диалог,
      правило 24 часов сохраняется.
- [ ] **7. Эскалация и деньги** — `escalate(...)` создаёт заявку **здесь**, а не на входе.
      `guard_rules` решает, будет ли кнопка возврата. Честностный guard на все тексты.
- [ ] **8. Эвалы** — ~40 сценариев против фейкового API: утечки внутренних терминов,
      честность обещаний, доля эскалаций, «агент никогда не возвращает», ответ на любой вход.
      Готово: зелёный прогон = право переключать.
- [ ] **9. Переключение** — `AGENT_MODE=all`, неделя наблюдения, удаление FSM.
      `triage.py` 2096 → ~200 строк.
- [ ] **10. Умнее** — преднагрузка заказов юзера на входе, проактив по авариям,
      CSAT, аналитика, сводки сотрудникам.

## Принятые решения

1. **Выбор аппарата** — спрашиваем только когда он реально нужен для проверки.
   Для вопроса про график работы аппарат ни при чём.
2. **Модели** — две: быстрая ведёт диалог, сильная принимает решение про возврат.
   Разговор должен быть быстрым, решение про деньги — точным.
3. **Старое меню** — после переключения удаляем совсем. Два входа = два поведения,
   которые со временем разъедутся.
